# 親招待の同時消費を必須化

Firestoreルールで親招待・コード索引・新規メンバーの変更を相互に検証するよう修正した。

- 招待と索引の type=parentInvite、targetRole=parent、有効期限、active 状態を検証。
- 有効期限はサーバーの request.time と比較。招待と索引の期限も一致させる。
- 招待の codeHash と索引の familyId・inviteId の対応を検証。
- getAfter で招待と索引が同時に used になり、招待の usedBy と新規親メンバーの userId が認証ユーザーに一致することを必須化。
- 既存メンバーを利用した消費は拒否。招待だけ、索引だけ、またはメンバーだけの変更は拒否。
- affectedKeys で更新可能フィールドを制限し、追加・削除によるメタデータ改ざんも拒否。
- 親招待の update は家族メンバーでも共通の消費検証を通る。親招待の任意編集は許可しない（現行アプリの作成・参加フローは維持）。

## 検証

ローカルFirestore Emulatorで親招待26ケースが成功。正常参加後の別ユーザーによる再利用拒否、失敗時に招待・索引・メンバーが部分的に書き込まれないことも確認。
既存のFirestoreルールテストも成功。全体監査は31項目中28項目成功となり、親招待の期限・消費迂回と、その後のチャット閲覧に関する3つの失敗を解消。

残る3項目はこども招待の期限切れ申請と未消費トークンによる複数申請。今回の親招待修正には含めていない。
