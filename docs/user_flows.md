# User Flows

このドキュメントは、ぎゅっとアプリの主要なユーザー操作の流れを整理するための設計書です。

## Roles

| Role | Description |
| --- | --- |
| 家族管理者 | 家族アカウントを最初に作成し、親とこどもを追加できるユーザー |
| 親 | 家族管理者に追加され、こどもを追加できるユーザー |
| こども | 家族管理者または親に追加され、チャットだけを利用するユーザー |

## Flow 1: First Launch

初めてアプリを開いたユーザーは、家族アカウントを作成するか、招待コードで既存の家族アカウントへ参加します。

```text
アプリ起動
↓
未ログイン状態を表示
↓
家族アカウントを作成する
または
招待コードで家族アカウントへ参加する
```

## Flow 2: Create Family Account

家族管理者になるユーザーが、最初に家族アカウントを作成します。

```text
家族アカウント作成を選択
↓
ユーザー情報を入力
↓
家族名を入力
↓
家族アカウントを作成
↓
作成したユーザーを家族管理者として登録
↓
ホーム画面へ移動
```

### Result

- 新しい家族アカウントが作成される
- 作成者が家族管理者になる
- 家族ごとの共有チャットが利用可能になる

## Flow 3: Add Parent Account

家族管理者は、親アカウントを追加できます。

```text
家族管理者でログイン
↓
家族管理画面を開く
↓
親アカウント追加を選択
↓
親の情報を入力
↓
親アカウントを作成
↓
家族メンバー一覧に親を表示
```

### Permission

| Role | Can Add Parent |
| --- | --- |
| 家族管理者 | Yes |
| 親 | No |
| こども | No |

## Flow 4: Add Child Account

家族管理者または親は、こどもアカウントを追加できます。

```text
家族管理者または親でログイン
↓
家族管理画面を開く
↓
こどもアカウント追加を選択
↓
こどもの情報を入力
↓
こどもアカウントを作成
↓
家族メンバー一覧にこどもを表示
```

### Permission

| Role | Can Add Child |
| --- | --- |
| 家族管理者 | Yes |
| 親 | Yes |
| こども | No |

## Flow 5: Child Permission Block

こどもアカウントは、親やこどもを追加できません。

```text
こどもでログイン
↓
家族管理画面を開く
↓
メンバー追加ボタンは表示しない
```

または、不正な操作が発生した場合はエラーとして扱います。

```text
こどもでメンバー追加を実行
↓
権限エラー
↓
追加は行わない
```

## Flow 6: Family Chat

家族メンバーは、全員が同じ共有チャットを利用します。

```text
ログイン
↓
ホーム画面を表示
↓
共有チャットを開く
↓
メッセージ一覧を表示
↓
メッセージを入力
↓
送信
↓
家族全員のチャットに反映
```

### Chat Rules

- 家族ごとに1つのチャットだけを持つ
- 家族メンバー全員が同じメッセージを見られる
- 個別チャットは作らない
- 複数グループチャットは作らない
- 家族外ユーザーには表示しない
- 送信済みメッセージの編集は許可しない
- 送信済みメッセージの削除は許可しない

## Flow 7: Read Receipts

メッセージごとに、誰が既読したかを常時確認できます。

```text
共有チャットを開く
↓
未読メッセージを表示
↓
現在のユーザーを既読者として記録
↓
既読した家族メンバーをメッセージ上に表示
```

### Read Receipt Rules

- 既読はメッセージ単位で記録する
- 既読者はユーザー名で表示する
- 自分が送ったメッセージでも、誰が読んだか分かる
- 既読者表示はタップ操作なしで常時表示する
- 家族外ユーザーの既読情報は存在しない

## Account Setup Decisions

| Topic | Decision |
| --- | --- |
| 既存家族アカウントへの参加方法 | 招待コードを使う |
| 親アカウントのパスワード | 初回ログイン時に本人が設定する |
| こどもアカウントの初期パスワード | 家族管理者または親が設定する |
| こどもアカウントのメールアドレス | 必須にしない |
| 認証方式 | Firebase Authentication を使う |
| 親招待コードとこども用 QR コードの有効期限 | 1時間 |
| こどもアカウントのパスワード再設定 | こどもが親へリクエストし、親が許可した場合のみ再設定できる |
| 既読者表示 | 常時表示する |
| メッセージ編集 | 許可しない |
| メッセージ削除 | 許可しない |
| チャット画像送信 | 不要 |

## Initial Password Options

親アカウントとこどもアカウントの初期パスワード設定には、次の方法があります。

| Option | Description | Pros | Cons |
| --- | --- | --- | --- |
| 管理者が初期パスワードを設定する | 家族管理者または親が、追加時に初期パスワードを決める | 実装がシンプルで、こどもにも渡しやすい | 管理者がパスワードを知ることになる |
| 自動生成パスワードを発行する | アプリが一時パスワードを作り、追加者が本人に伝える | 推測されにくい | 入力しづらく、紛失しやすい |
| 初回ログイン時に本人が設定する | 招待コードで参加後、本人がパスワードを設定する | 本人だけがパスワードを知れる | こどもには手順が少し難しい |
| パスワードなしの招待コード方式にする | 招待コードと家族内確認だけで参加する | こどもには簡単 | 端末紛失時やなりすまし対策が弱い |

### Decision

MVP では、親アカウントは「初回ログイン時に本人が設定する」、こどもアカウントは「管理者または親が初期パスワードを設定する」方式にします。

理由は、親は本人だけがパスワードを知る形にでき、こどもはメールアドレスなしでも家族内で安全に始めやすいからです。こどもアカウントは、あとで保護者がパスワードを再設定できる前提にします。

## Flow 8: Returning User

既に家族アカウントに参加しているユーザーは、ログイン後すぐにホーム画面へ移動します。

```text
アプリ起動
↓
ログイン状態を確認
↓
所属家族を確認
↓
ホーム画面を表示
```

## Flow 9: Child Password Reset

こどもアカウントのパスワードを再設定する場合は、親の許可を必要とします。

```text
こどもがパスワード再設定を選択
↓
親へ再設定リクエストを送信
↓
親がリクエストを確認
↓
親が許可
↓
こどもが新しいパスワードを設定
↓
再設定完了
```

親が許可しない場合、パスワード再設定は行いません。
